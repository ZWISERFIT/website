Experience Protocol v0.1

A frozen, language-independent, runtime-independent specification for Experience objects. The rules that all Experience must conform to.

FROZEN · Version 0.1.0-draft · 2026-09-09

What the Protocol defines

The Protocol is the specification — the rules that all Experience must conform to. It does not store Experience. It does not serve Experience. It defines what Experience is.

Experience Object schema

5 required fields: id, content, fingerprint, source, outcome. Plus 2 state fields (lifecycle, authorization), 7 optional fields, and 3 embedded objects.

Provenance & Lineage

Provenance answers: where did this Experience come from? Lineage answers: what did this evolve from? Both are embedded in every Experience object.

Verification model

VerificationAttestation records: who verified, by what method, what result, with what evidence. Append-only. Empty or absent = unverified.

Important: SHA-256 fingerprint detects integrity changes. It does NOT prove the event or outcome was valid.

Authorization model

Three states: private, shared (with allowed consumers), public. Authorization controls who can retrieve, not who owns.

Four concepts the Protocol keeps strictly separate

Provenance

"Where did this Experience come from?"

Records the origin: producer, process, time, place. Embedded in every Experience.

Verification

"Was the event/outcome sufficiently validated?"

Attestation records with verifier, method, result, evidence. A separate layer from provenance.

Fingerprint

"Can we detect integrity changes?"

LAO-FP-v1: NFC normalize → trim → UTF-8 → SHA-256. Content-only hashing. Does NOT prove validity.

Ownership / Rights

"Who has claims on this data?"

Not handled in the Protocol. Ownership and rights belong to the downstream behavioral asset chain.

Why the Protocol matters for Agent reliability

Without a shared specification, every Agent defines "Experience" differently. Experience that one Agent produces cannot be understood by another. The Protocol makes Experience interoperable — across Agents, across languages, across organizations.

Protocol defines the rules → Catalog enforces the rules → Agents benefit from the rules

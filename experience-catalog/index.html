Experience Catalog v0.1

A Protocol-conformant registry for Experience. Not a marketplace. Not a platform. An index and access enforcement layer.

SQLite · FastAPI · 6 endpoints · 74/74 smoke tests passed

What the Catalog does

The Catalog is the instantiation of the Protocol — the actual registry where Experience objects are stored, discovered, and retrieved. It enforces lifecycle, authorization, and fingerprint integrity.

① Registration

POST /v1/experiences — Register a new Experience. Validates schema, computes fingerprint (LAO-FP-v1), enforces publish prerequisites.

② Discovery

GET /v1/experiences — Discover Experience objects by domain, outcome, lifecycle, authorization, tags.

③ Retrieval

GET /v1/experiences/{id} — Retrieve a specific Experience with full canonical JSON, fingerprint, and verification attestations.

④ Lifecycle

PATCH /v1/experiences/{id} — Transition lifecycle: draft → published → retired. Enforces valid transitions.

⑤ Attestation

POST /v1/experiences/{id}/attestations — Submit verification attestation. Append-only.

⑥ Authorization

PATCH /v1/experiences/{id}/consumers — Update allowed consumers for shared Experiences.

What this proves and what it does not

What this proves

  • The Protocol is implementable by independent parties
  • Cross-language fingerprint consistency is achievable
  • The Catalog can register, discover, retrieve, attest, and authorize Experience
  • The Frozen Specification is sufficient for third-party implementation

What this does NOT prove

  • That the Runtime currently produces Protocol Experience (it does not)
  • That Experience is stored in the Catalog from production (it is not)
  • That Agents retrieve and reuse Catalog Experience (they do not)
  • That this is a production marketplace (it is a reference implementation)

Why the Catalog matters for Agent reliability

The Catalog is where Experience becomes shareable. Without it, every Agent's Experience is trapped in its own session. With it, verified Experience can be discovered, retrieved, and reused — making Agents reliably better over time.

Protocol defines the rules → Catalog enforces the rules → Agents benefit from the rules
